## Overview

#### PDF Export Considerations

**Library Options**:
1. **WeasyPrint** (Recommended):
   - HTML/CSS to PDF
   - Good styling support
   - Easier to maintain consistency with HTML export
   - Dependency: system libraries (Cairo, Pango)

2. **ReportLab** (Alternative):
   - Python-native PDF generation
   - More control over layout
   - Steeper learning curve
   - No system dependencies

**Decision**: Use WeasyPrint if system dependencies available, otherwise defer PDF export or use ReportLab.

## Common Issues and Solutions

### Issue 1: PDF Generation Fails

**Symptom**: WeasyPrint or ReportLab errors

**Solution**:
1. Check system dependencies (WeasyPrint requires Cairo, Pango)
2. Try ReportLab as alternative
3. Test with minimal content first
4. Consider deferring PDF to future version

**Installation Commands**:
```bash
# macOS
brew install cairo pango gdk-pixbuf libffi

# Ubuntu/Debian
sudo apt-get install libcairo2 libpango-1.0-0 libpangocairo-1.0-0

# Windows
# Use pip-installable version or ReportLab
```

### Issue 2: HTML/CSS Rendering Issues

**Symptom**: HTML displays incorrectly

**Solution**:
1. Validate HTML with W3C validator
2. Test CSS in isolation
3. Use CSS reset for consistency
4. Test in multiple browsers

### Issue 3: Batch Export Performance

**Symptom**: Batch export too slow

**Solution**:
1. Add progress reporting
2. Parallelize independent exports
3. Optimize file I/O (batch writes)
4. Profile to identify bottlenecks

### Issue 4: File Path Issues

**Symptom**: Files not saved in expected locations

**Solution**:
1. Use absolute paths
2. Create directories before writing
3. Handle path separators correctly (os.path.join)
4. Verify write permissions

### Issue 5: Format Conversion Errors

**Symptom**: Content lost or corrupted in conversion

**Solution**:
1. Test round-trip conversion (export/import)
2. Validate output against schema
3. Handle special characters properly
4. Preserve all metadata

## Notes and Observations

### Design Decisions

**Decision**: WeasyPrint for PDF generation
- **Rationale**: HTML/CSS to PDF, consistent with HTML export
- **Alternative**: ReportLab (Python-native)
- **Trade-off**: System dependencies vs. consistency
- **Fallback**: Defer PDF if dependencies unavailable

**Decision**: Separate exporter per format
- **Rationale**: Single responsibility, easy to extend
- **Alternative**: Single exporter with format parameter
- **Trade-off**: More files but better organization

**Decision**: Batch export with directory organization
- **Rationale**: Keep related formats together
- **Alternative**: Flat structure with naming convention
- **Trade-off**: More directories but better organization

**Decision**: JSON export includes schema
- **Rationale**: Self-documenting, validation-ready
- **Alternative**: Plain JSON without schema reference
- **Trade-off**: Verbosity vs. validation capability
