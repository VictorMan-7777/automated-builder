## Implementation Approach

### Template Location

**Source**: `templates/project/project.yaml.tmpl` (created in Issue-001)

**Content**:
```yaml
# Project Identity
# Single source-of-truth for project metadata
# Generated by run-create-project

identity:
  slug: {project-slug}
  name: {Project Name}
  prefix: {PREFIX}
  created: {YYYY-MM-DD}

schema_version: 1
```

### Implementation Steps

Extend `system/scripts/run-create-project.md` with project.yaml creation:

```bash
# After path resolution and validation (Issue-003)

# 1. Create project root directory
mkdir -p "${PROJECT_PATH}" || validation_error "Cannot create project directory: ${PROJECT_PATH}"

# 2. Verify template exists
TEMPLATE_PATH="${BUILDER_ROOT}/templates/project/project.yaml.tmpl"
if [[ ! -f "${TEMPLATE_PATH}" ]]; then
  validation_error "Template not found: ${TEMPLATE_PATH}"
fi

# 3. Get current date
CURRENT_DATE="$(date +%Y-%m-%d)"

# 4. Escape values for safe sed substitution
# Escape '/', '&', and '\' characters to prevent sed interpretation
escape_sed() {
  local value="$1"
  # Escape backslashes first, then forward slashes, then ampersands
  value="${value//\\/\\\\}"
  value="${value//\//\\/}"
  value="${value//&/\\&}"
  echo "$value"
}

ESCAPED_SLUG="$(escape_sed "${NORMALIZED_SLUG}")"
ESCAPED_NAME="$(escape_sed "${NORMALIZED_NAME}")"
ESCAPED_PREFIX="$(escape_sed "${NORMALIZED_PREFIX}")"
ESCAPED_DATE="$(escape_sed "${CURRENT_DATE}")"

# 5. Render template with safe token substitution
# Use '|' as sed delimiter to avoid conflicts with escaped '/'
cat "${TEMPLATE_PATH}" \
  | sed "s|{project-slug}|${ESCAPED_SLUG}|g" \
  | sed "s|{Project Name}|${ESCAPED_NAME}|g" \
  | sed "s|{PREFIX}|${ESCAPED_PREFIX}|g" \
  | sed "s|{YYYY-MM-DD}|${ESCAPED_DATE}|g" \
  > "${PROJECT_PATH}/project.yaml"

# 6. Validate created file
if [[ ! -f "${PROJECT_PATH}/project.yaml" ]]; then
  validation_error "Failed to create project.yaml"
fi

# 7. Check for unresolved tokens
if grep -q '{.*}' "${PROJECT_PATH}/project.yaml"; then
  UNRESOLVED=$(grep -o '{[^}]*}' "${PROJECT_PATH}/project.yaml" | head -1)
  validation_error "Unresolved token in project.yaml: ${UNRESOLVED}"
fi

# 8. Validate file permissions
if [[ ! -r "${PROJECT_PATH}/project.yaml" ]]; then
  validation_error "project.yaml is not readable"
fi

# Success: project.yaml created (no YAML validation in Issue-005)
echo "✅ project.yaml created (YAML validation deferred to Issue-009)"
```

### Token Substitution Strategy

**Safe sed-based replacement** (POSIX-compliant):
- Escape special characters ('/', '&', '\') before substitution
- Use '|' as sed delimiter (instead of '/') to avoid conflicts
- No external dependencies
- Deterministic and safe for arbitrary input values

**Escaping function**:
```bash
escape_sed() {
  local value="$1"
  value="${value//\\/\\\\}"  # Escape backslashes first
  value="${value//\//\\/}"   # Escape forward slashes
  value="${value//&/\\&}"    # Escape ampersands
  echo "$value"
}
```

**Alternative approaches considered**:
- Template engines (mustache, envsubst): Requires external tools
- awk-based: More complex, no advantage over escaped sed
- Pure bash parameter expansion: Not suitable for file-based templates

**Chosen approach**: Escaped sed with '|' delimiter for safety and POSIX compliance

## Validation Strategy

### Issue-005 Scope (Implemented)

1. **File existence**: `[[ -f "${PROJECT_PATH}/project.yaml" ]]`
2. **Unresolved tokens**: `grep -q '{.*}' "${PROJECT_PATH}/project.yaml"`
3. **Readability**: `[[ -r "${PROJECT_PATH}/project.yaml" ]]`
4. **Safe substitution**: Escaped sed prevents '/', '&', '\' interpretation

**Rationale**: Template is known-good (Issue-001), input parameters are validated (Issue-002/003/004), deterministic token replacement with escaping is sufficient for Issue-005.

### Issue-009 Scope (Deferred)

**YAML parsing and semantic validation**:
- Parse YAML structure (requires external tool: yq, python, ruby, or bash YAML parser)
- Verify schema_version = 1
- Verify identity section exists
- Verify field formats (slug, prefix, date patterns)
- Verify field presence and non-empty constraints

**Rationale**: Deferred to end-to-end validation to avoid external dependencies in Issue-005. Template correctness + validated inputs + deterministic substitution = high confidence in Issue-005 output.

## Risks / Failure Modes

- **Template read failure**: Template file missing or unreadable
  - Mitigation: Explicit existence check before rendering
- **Token substitution incomplete**: Unresolved tokens remain
  - Mitigation: Post-substitution grep check for `{...}` patterns
- **Special characters in values**: Values containing '/', '&', or '\' could corrupt sed substitution
  - Mitigation: escape_sed() function + '|' delimiter prevents sed interpretation
- **YAML rendering produces invalid syntax**: Template structure corrupted during substitution
  - Mitigation: Template correctness verified in Issue-001; escaped substitution preserves structure; full YAML validation in Issue-009
- **Filesystem write failure**: Permissions, disk space
  - Mitigation: Check directory creation success; validate file readable
- **Date format issues**: System date command unavailable or returns unexpected format
  - Mitigation: Use POSIX-compliant `date +%Y-%m-%d`
